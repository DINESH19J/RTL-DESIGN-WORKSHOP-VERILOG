# Pre-Synthesis vs Post-Synthesis Simulation — VSDBabySoC

## 📌 Overview

This section compares the **pre-synthesis (RTL) simulation** and the **post-synthesis (gate-level) simulation** of the `vsdbabysoc` design, run on the same testbench (`vsdbabysoc_tb`) instantiating the design as `uut`. The goal is to confirm that synthesis did not alter the functional behavior of the design — i.e. that the gate-level netlist behaves identically to the original RTL.

---

## 🔍 Signals Observed

Both waveforms show the same set of signals from the `uut` instance:

| Signal | Type | Description |
|---|---|---|
| `CLK` | wire | System clock driving the design |
| `ENb_CP` | wire | Enable (active-low) for the charge pump |
| `ENb_VCO` | wire | Enable (active-low) for the VCO (Voltage-Controlled Oscillator) |
| `OUT` | wire | Analog/PLL output |
| `REF` | wire | Reference signal input |
| `RV_TO_DAC[9:0]` | wire (10-bit bus) | 10-bit digital value passed from the RISC-V core to the DAC |
| `VCO_IN` | wire | Input to the VCO |
| `VREFH` | wire | Reference high voltage for the DAC |
| `reset` | wire | Design reset signal |

The bus `RV_TO_DAC[9:0]` — expanded bit-by-bit (`[9]` down to `[0]`) in both traces — is the primary signal of interest here, since it reflects the core's computed output feeding the DAC.

---

## 1. Pre-Synthesis (RTL) Simulation

The pre-synthesis waveform is generated by simulating the original RTL design directly (before any gate-level mapping). `CLK` toggles continuously throughout the run, and `RV_TO_DAC[9:0]` shows a changing digital pattern across the ~85 µs simulation window, with each bit `[9:0]` toggling at different rates — consistent with a counting or incrementing digital value being fed toward the DAC.

## 2. Post-Synthesis (Gate-Level) Simulation

The post-synthesis waveform is generated by simulating the **synthesized gate-level netlist** (`post_synth_sim.vcd`) — the same testbench, but now exercising standard cells instead of behavioral RTL. The same signal set (`CLK`, `RV_TO_DAC[9:0]`, etc.) is observed over the same ~85 µs window.

## ✅ Comparison

| Aspect | Pre-Synthesis | Post-Synthesis |
|---|---|---|
| Design under test | RTL (behavioral) | Gate-level netlist |
| Simulation window | 0 – 84999 ns | 0 – 84999 ns |
| `CLK` behavior | Continuous toggling | Continuous toggling (identical) |
| `RV_TO_DAC[9:0]` pattern | Digital bus toggling per-bit | Same toggling pattern, bit-for-bit |
| Signal list | CLK, ENb_CP, ENb_VCO, OUT, REF, RV_TO_DAC[9:0], VCO_IN, VREFH, reset | Identical signal list |

Visually overlaying the two `RV_TO_DAC[9:0]` traces shows the same bit transitions occurring at the same points in time across the full simulation window — the post-synthesis netlist reproduces the pre-synthesis RTL's behavior exactly.

---

## 🏁 Conclusion

The gate-level netlist produced by synthesis is **functionally equivalent** to the original RTL design. The `RV_TO_DAC[9:0]` output bus — the key signal carrying the core's computed value to the DAC — shows identical toggling behavior in both the pre-synthesis and post-synthesis simulations, with no mismatches, no unexpected `X`/`Z` states, and no timing-related glitches visible at this resolution.

This confirms there is **no synthesis-simulation mismatch** for this design, and the netlist is ready to proceed to the next stage of the flow (place & route / physical design).
